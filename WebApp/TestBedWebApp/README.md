# TestBedWebApp

`TestBedWebApp` is the React/Vite frontend for configuring, starting, monitoring, and stopping Satellite Security Testbed simulations.

## Stack

- React 19
- Vite 6
- Redux Toolkit
- React Router
- React Use WebSocket
- Leaflet / React Leaflet
- Chart.js / react-chartjs-2
- msgpackr

## Install

```bash
npm install
```

## Development

```bash
npm run dev
```

The development server normally runs at:

```text
http://localhost:5173
```

The app currently connects to the Manager at:

```text
ws://127.0.0.1:8765
```

Start the Manager before running a live simulation:

```bash
cd ../../src/Manager
python ManagerServer.py
```

## Main User Flow

1. User opens `/` or `/SimConfig`.
2. User uploads a TLE text file.
3. The app extracts the TLE epoch and fills start epoch time.
4. User sets duration, simulation count, optional attacks, Mongo saving, and command-file save/load options.
5. Form submit stores values in Redux and redirects to the live simulation page.
6. User presses **Start** in `StatusPanel`.
7. The app sends `createStartMsg()` and graph request data to the Manager.
8. Incoming Manager messages update satellite state, command logs, and graph data.
9. When the Manager sends `simulationComplete`, the app returns to the configuration screen and shows a closeable completion popup.

## Run Options

The configuration form includes optional runtime controls:

- **Save simulation data to MongoDB** - included in the start message as `saveToMongo`.
- **Save generated file** - asks the Manager to save the command timeline generated by the operational component.
- **Load saved file** - opens a file picker and uploads the selected command timeline text to the Manager.
- **Manager command file name** - optional name used by the Manager when saving the file under `src/Manager/saved_command_files/`.

The loaded command file is selected by the browser, so choose it manually from the Manager saved-command folder when the WebApp is running on the Manager computer.

## Message Builders

Message builders live in:

```text
src/assets/msgForServer.jsx
```

Important exports:

- `createStartMsg()`
- `stopData`
- `pauseData`
- `resumeData`
- `setRequestedGraphsData`
- `createSetAttackFactorMsg(factor)`

`createStartMsg()` includes the simulation setup plus the per-run Mongo flag and command-file fields used by the Manager.

## Troubleshooting

- If **Start** is disabled, the WebSocket is not open. Confirm `src/Manager/ManagerServer.py` is running.
- If graph panels wait forever, confirm operational telemetry is reaching the Manager.
- If the map is static, inspect incoming WebSocket messages for satellite state fields.
- If attack selection works but attacks do not run, confirm the attack name exists in `src/cyber/main.py`.
